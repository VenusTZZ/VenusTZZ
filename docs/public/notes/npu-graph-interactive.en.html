01 / Background

Short kernel sequences: the time goes to launches, not compute

In ZeRO + BF16 mixed-precision training, each step runs far more than the big GEMM-class kernels: there is also a chain of very small operators — computing the gradient norm, clipping gradients by that norm, and writing the gradients accumulated on the fp32 master weights back to the bf16 weights. Each operator does almost no compute, so the fixed host-side cost of launching a kernel ends up dominating.

Eager mode

Every small operator is launched on its own: host submit → driver enqueue → device execute. Dozens of launches round-trip serially, and the device spends most of its time waiting.

Graph capture + replay

The first step captures the whole operator chain as a device graph; every step after that is a single replay: one submission replays the entire graph and launch overhead drops to a minimum.

04 / Code changes

accelerator/npu_accelerator.py: an 8-line change

The change lives entirely inside the three interfaces, and the signatures match the abstract base class exactly — so the device-agnostic main path needs no edits at all.

# Graph operations — before the fix
def create_graph(self):
    return None

def capture_to_graph(self, graph, pool=None, stream=None):
    from deepspeed.runtime.utils import noop_context
    return noop_context()   # an empty context that captures nothing

def replay_graph(self, graph):
    return                  # empty function: each step's "replay" ends here
# Graph operations — after the fix
def create_graph(self):
    return torch.npu.NPUGraph()

def capture_to_graph(self, graph, pool=None, stream=None):
    # the context manager handles sync, cache cleanup, side-stream switching, and capture begin/end
    return torch.npu.graph(graph, pool, stream)

def replay_graph(self, graph):
    graph.replay()

The implementation mirrors HPU (#4912), MLU (#6472), and SUPA (#8054) exactly. The graph API is a core torch_npu interface across versions, so it is called directly with no existence check, consistent with backends such as CUDA.

05 / History

How the gap appeared, and how it was closed

2024

#4318 introduces the graph ops abstraction

Adds three interfaces — create_graph / capture_to_graph / replay_graph — for short kernel sequences. CUDA implements them first; NPU and other backends are left as stubs.

2024

#4912 brings in HPU

Habana implements the trio on its own runtime graph API, establishing the integration template for non-CUDA backends.

2024–2025

#6472 MLU and #8054 SUPA join in turn

Cambricon MLU and Biren SUPA implement the same abstraction, leaving NPU as the only backend still on a stub.

2026-09

#8604 filed → #8605 fix merged

Reproduces the silent failure on real hardware (norm frozen, clipping stopped, write-back stopped, with no error), implements the interfaces, and adds device-agnostic contract tests plus real-device performance data. Merged into master on September 22.
