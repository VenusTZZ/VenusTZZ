01 / 瓶颈

一个 decode step，瓶颈在 CPU 而不在设备

自回归解码的每一步只新增一个 token，却要发射上千个小 kernel。设备上每个 kernel 都很短，设备算完了还在等 CPU 排下一个。图捕获把整段 forward 录下来，之后每步只做一次 replay。点击播放，对比同一个 decode step 的两种执行方式。

02 / 门控

问题不在能力缺失，而在门控方式

NPU 通过 torch_npu.NPUGraph 早就具备图捕获能力，但运行时用设备名字符串做判断，把 NPU 直接挡在外面。切换两种门控方式，观察同一块 NPU 的不同命运。

04 / NPU 难点

门控打开后，真正要解决的是两个算子级问题

这是整个适配中最需要底层定位能力的部分：一个是 CANN 对辅助流的捕获限制，一个是进程级计数器导致的 KV cache 越界。

融合注意力：v1/v2 → v3

v1/v2 在内部辅助流上发射任务，CANN 在 capture_end 拒绝（错误 107025）。v3 不使用辅助流，BSH 布局下可干净捕获。

KV cache 表按需扩容

layer_id 来自进程级只增计数器 num_layers。同一进程建第二个引擎时 layer_id 超出表长，改为按需 append。
