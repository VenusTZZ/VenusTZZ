01The problem: all three ops are missing on NPU

ZeRO-3 spreads parameter slices across ranks, so training repeatedly all-gathers weights and all-to-alls gradients — communication is the main bottleneck. ZeRO++ brings the communication payload down with low-bit quantization, but all of it depends on the Quantizer op, and the two fused optimizers, Lion and LAMB, depend on their own fused ops too. The NPU backend has none of the three, so turning the config on crashes during engine initialization.

Init-time crash

FusedLion

With "optimizer": {"type": "Lion"}, FusedLionBuilder().load() throws ValueError, so Lion training cannot start on Ascend.

Init-time crash

FusedLamb

"type": "Lamb" falls into the same unimplemented branch; LAMB's trust-ratio semantics have no entry point on NPU.

Init-time crash

Quantizer (hpZ / qgZ)

Enabling zero_quantized_weights or zero_quantized_gradients makes the quantizer fail to load, leaving all of ZeRO++ quantized communication unavailable.

Why communication is the ZeRO bottleneck

hpZ · quantized-weight all-gather

fp16 weights are symmetrically quantized to int8 per group before all-gather, halving the bytes each rank pulls; the receiving rank dequantizes, and training math stays in fp16/bf16.

qgZ · two-stage all-to-all for quantized gradients

Gradients are packed into int4 and rearranged into the two-stage all-to-all layout: intra-node exchange first, then quantized_reduction (dequantize → fp16 accumulate → requantize), then inter-node exchange.

02Root cause: OpBuilder backend dispatch and fallback

Every DeepSpeed op that can be accelerated has an OpBuilder, implemented separately under each backend directory. When a backend lacks an op, the name resolves to NotImplementedBuilder and calling load() throws immediately. Switch backends below to see where the three ops stand on each one.

deepspeed.initialize()
└─ FusedLionBuilder / FusedLambBuilder / QuantizerBuilder
   └─ NotImplementedBuilder.load()
      ValueError: This op had not been implemented on NPU backend.

Background: PR #8054 had already filled in these three builders for the SUPA backend, leaving NPU as the only gap; this PR adds same-named modules under op_builder/npu/ and registers them in __init__.py, so dispatch now lands on a real implementation.

03hpZ workflow: int8 quantize → transfer → dequantize

Quantized values exist only as communication payload and never enter training math. Step through the full lifecycle of one quantization group.

The key contract: why it must truncate toward zero

scale  = 2^b / (2 · max(|x|))        # scale is 1.0 when max is 0
params = 1 / scale                    # each group actually sends the reciprocal of scale (fp32)
q      = trunc(x · scale)             # truncation toward zero, matching CUDA's static_cast
q      = clamp(q, -2^(b-1), 2^(b-1)-1)
# switching to round-to-nearest changes every quantized value — in a mixed cluster, CUDA and NPU dequantize differently

05qgZ workflow: int4 packing and two-stage all-to-all

Two adjacent quantized values fit in one byte: even elements in the low nibble, odd elements in the high nibble, interpreted as signed two's complement. Click a byte to inspect its two nibbles.

nibble packing (signed two's complement)

Click any byte to see the breakdown…

Range [−8, 7]; negative values occupy the nibble as two's complement and are sign-extended on unpack. torch_npu's npu_anti_quant treats int4 as unsigned and is incompatible with this format.

swizzle_quant: group permutation

After quantization, groups are permuted by destination rank so each destination card receives one contiguous block in memory, letting all-to-all move whole blocks instead of scattered fragments.

06The two fused optimizers: aligned contracts and chained in-place

Both are stateless, pure-torch modules: compute in fp32 and write back in the parameter's original dtype. Chained in-place updates cut kernel launches, striking the balance between performance and verifiability.

c = β1·m + (1−β1)·g
p *= (1 − lr·wd)          # multiplicative weight decay
p += lr · sign(c)         # takes the +lr branch when c==0
m  = β2·m + (1−β2)·g      # momentum updated last (c uses the old momentum)

Design notes

The sign update is bit-for-bit identical to the reference kernel; the whole step is skipped when the overflow flag is set. On 910B4, chained in-place is ~26% faster than explicit two-step arithmetic and gives bitwise-equal results.

m = β1·m + (1−β1)·g
v = β2·v + (1−β2)·g²
denom = sqrt(v+eps) or sqrt(v)+eps
u = m/denom + wd·p
coeff = clamp(||p||/||u||, min, max)
p -= step_size · coeff · u

Full semantics, nothing dropped

The trust ratio's max/min coefficient clamp, bias correction, both eps modes, and the zero-norm fallback (coefficient 1.0). Compared with torch_npu's official NpuFusedLamb on identical semantics: first moments match bit for bit, parameters differ by 1 ulp.

07Verification: a three-layer evidence chain and honest negative results

Contract tests run on CPU alone, real hardware checks convergence and cross-implementation agreement, and end-to-end runs confirm the quantized path actually fires with the payload halved.

Layer 1

Contract tests

Bit-for-bit comparison against an independent numpy oracle, runnable with no accelerator, covering all three modules.

Layer 2

On-device cross-check

Five Lion engine steps are bitwise equal to a hand-written oracle; LAMB matches NpuFusedLamb with bit-for-bit identical state.

Layer 3

End-to-end

hpZ ZeRO-3 on two cards for 8 steps; final loss differs by 1.7e-4 with quantization on vs off, and the weight payload goes 33152→16592 B (−50%).

Two limitations we don't hide

Negative result

Intra-node, hpZ is slower

Measured HCCL all_gather runs 4.7–16.2 GB/s against a quantization break-even bandwidth of 14.4 GB/s; on this intra-node link hpZ is 0.62–0.97× the fp16 baseline. The payoff depends on long inter-node links; the full data and environment are in the PR.

Known deviation

1 ulp division deviation

Ascend fp32 division differs by 1 ulp on about 5% of values. Every rank sees the same value, the relative error (~1e-7) is five orders of magnitude below the quantization error (~1e-2), and the wire-format values are transient and never checkpointed — bounded and safe.
