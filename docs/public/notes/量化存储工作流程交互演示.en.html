Background and concepts

Context

Memory layout of LoRA fine-tuning

The base model is fully frozen and only a small set of adapters trains. Frozen parameters produce no gradients, yet they still hold most of the parameter memory — the largest single compression win.

Grouped quantization

Weights are split into groups; each group computes its own scale from its absmax and is encoded as int8. Dequantization multiplies back per group, keeping the error within 1 LSB inside a group.

Partitioning and coalesced buckets

ZeRO-3 splits a parameter into N shards, one per rank. At fetch time, several parameters are packed into one coalesced bucket, retrieved with a single all-gather, then unpacked parameter by parameter.

The two interactive modules below walk through “the full lifecycle of one parameter partition” and “dequantization of a multi-parameter coalesced bucket”. Every number is computed live from the fixed data embedded in this page.

Three defects and their fixes

Defect map
SeverityDefectMechanism and impactFix in PR #8995
High Quantizes empty memory, then overwrites it Quantization runs on torch.empty, so the scale comes from garbage; copy_ then implicitly casts the fp16 weights to int8, truncating every value in (-1, 1) to 0, and the frozen layer silently goes all-zero. Zero the padding → copy in the real weights → quantize only afterwards; all three partition paths now share this order
High AttributeError on a single GPU The no-gather handle reads the class attribute Init.quantizer_module, but the quantizer is attached only to the instance, so the first forward pass on a single GPU crashes. Attach the quantizer to the Init class as a process-level singleton
Mid Coalesced buckets dequantized incorrectly fp16 weights are cast back to the int8 storage dtype, so matmul hits a type error; the flat bucket dequantizes with one uniform group size, misplacing the scale boundaries. Dequantize per parameter → concatenate as fp16 → requantize uniformly; restore according to param.dtype

Validation evidence and limits

Evidence

A regression test pins down the bug

The new test_quantized_nontrainable.py passes with world size 1 and 2 on 910B4 and A100; the same test fails on master with “quantized storage is all zeros”.

Quantization contract and real models

All 242 quantizer unit tests pass; LoRA runs on Qwen3-0.6B/1.7B/4B show a 98.8% non-zero ratio, half the storage bytes for frozen weights, and normal loss convergence.

Offload semantics and rounding

CPU parameter offload is rejected outright at initialization; NVMe skips quantization and warns. The NPU quantizer now covers int4/asymmetric, and truncation switched to half-to-even to match CUDA.

Not covered: bf16 storage, the NVMe path, cross-node interconnect, and a full checkpoint round trip — all flagged explicitly in the PR. The PR is still a draft and unmerged; there are no API, configuration, or checkpoint-format changes.
