01 / 背景

短内核序列：时间不是算掉的，是「发射」掉的

ZeRO + BF16 混合精度训练中，每一步除了 GEMM 这类大算子，还有一串很碎的小算子：计算梯度范数、按范数做梯度裁剪、把 fp32 主权重上累积的梯度回写给 bf16 权重。单个算子计算量极小，Host 端 launch 内核的固定开销反而成了主导。

Eager 模式

每个小算子单独发射：Host 提交 → 驱动入队 → 设备执行，几十次 launch 串行往返，设备大量时间在等待。

图捕获 + 重放

第一步把整串算子捕获成设备图，之后每步一次 replay：一次提交重放整张图，launch 开销被压到最低。

04 / 代码修改

accelerator/npu_accelerator.py：8 行改动

改动只在三个接口内部，函数签名与抽象基类完全一致，所以设备无关的主链路一行都不用动。

# Graph operations —— 修复前
def create_graph(self):
    return None

def capture_to_graph(self, graph, pool=None, stream=None):
    from deepspeed.runtime.utils import noop_context
    return noop_context()   # 什么都不捕获的空上下文

def replay_graph(self, graph):
    return                  # 空函数：每步的“重放”到此结束
# Graph operations —— 修复后
def create_graph(self):
    return torch.npu.NPUGraph()

def capture_to_graph(self, graph, pool=None, stream=None):
    # 上下文管理器内部完成同步、缓存清理、侧流切换与 capture begin/end
    return torch.npu.graph(graph, pool, stream)

def replay_graph(self, graph):
    graph.replay()

写法与 HPU（#4912）、MLU（#6472）、SUPA（#8054）完全同构；图 API 是 torch_npu 跨版本核心接口，因此直接调用、不加存在性检查，与 CUDA 等后端保持一致。
