01

先看融合权重的物理布局

GPTBigCode 采用多查询注意力（MQA）：全模型只有 1 个 KV head，所有 query head 共享同一组 K/V。它的融合投影 c_attn 把 Q、K、V 拼在同一个权重里，排布方式是「query 行在前，整块共享 K/V 在后」。

Query 行：按 head 切分（各 rank 不同） K/V 块：整块复制（每个 rank 完整保留）
c_attn.weight = [out_features, in_features]，hidden = 32，heads = 4
Q h0
Q h1
Q h2
Q h3
K（共享，8 行）
V（共享，8 行）
out = 32（Q）+ 16（K/V）= 48 行　·　in = 32
  • Q 行是分片的：TP 切分时 _bigcode_type_transpose 只切这部分，每个 rank 持有 hidden/TP 行。
  • K/V 块是复制的：任何 TP 度下，每个 rank 都持有完整的 16 行 K/V，不参与切分。
  • 复制带来梯度问题：各 rank 只对自己的 Q head 产生 K/V 梯度，必须 all-reduce 求和，否则各 rank 上本应相同的 K/V 行会更新出不同的值。

缺陷 B：同一个 matmul，两种内存布局

K/V 梯度 all-reduce 操作的是融合梯度 narrow() 出的视图。CUDA 的 matmul 反向返回连续的 [out, in] 梯度；torch_npu 返回转置的非连续布局。NCCL 与 HCCL 都拒绝非连续集合通信输入——这与 transformers 版本无关，NPU 在 4.44.2 上也会失败。

CUDA / NCCLcontiguous
grad (32, 32)　stride (32, 1)　narrow → KV (16, 32)
is_contiguous() = True　·　视图按行连续存放
narrow 视图→all_reduce 原地执行→零额外拷贝
NPU / HCCL（torch_npu）non-contiguous
grad (32, 32)　stride (1, 32)　clone() 保留转置布局
is_contiguous() = False　·　narrow 后 KV 视图仍非连续
narrow 视图→HCCL: Tensors must be contiguous

修复后的分支决策：不硬编码后端，按张量布局走

KV 视图 numel == 0？→跳过（复制块在所有 rank 同时为空） | 连续？→原地 all_reduce | 非连续？→.contiguous() 暂存→all_reduce→copy_ 回 autograd 视图

遗留问题：梯度裁剪的重复计数（单独 issue 跟踪，本 PR 不改）

全局 norm 把复制的 K/V 行在每个 TP rank 各计一次。TP=2 时 c_attn 的 norm 恰为单卡的 √2 倍，扣掉一份多余的 K/V 计数可精确复现单卡值。

‖grad‖²_tp = ‖Q‖² + TP · ‖K/V‖²　　⇒　　TP=2 时 c_attn norm = √2 × 单卡值（实测 1.414×）
